# Engine Room — Complete Specification v1.0

## GOVERNING IDEA


Governing Idea    Observability
Visitor Role      Inspector
Entry Point       System Topology (Level 0)
Question          How does this system actually work?
Mood              The system tells the truth.


Engineer mode is not a dashboard. It is not a project browser. It is not an architecture showcase.

It is an **observability workspace** — a place where a peer engineer can inspect a running system, understand how its parts relate, trace decisions through history, and evaluate tradeoffs without being guided, marketed to, or protected from complexity.

**The software/character line applies here as in Signal Interface:**
Every component that behaves like a character (revealing truth, resisting theater, communicating with restraint) is correct.
Every component that behaves like software (decorative metrics, fake latency, loading-state theater) is wrong.

---

## THE OBSERVED / MODELED DISTINCTION

The most important design primitive in Engineer mode.


OBSERVED    Measured at runtime. Always live. Never estimated. Never faked.
MODELED     Architectural truth. Always accurate. Never pretending to be measured.
SIMULATION  Explicitly interactive. Always labeled. Never running silently.


**The three-second rule:**
An Inspector should always be able to answer "is this measured or modeled?" within three seconds. If not, the UI has failed.

**The anti-theater rule:**
Never fake a metric that could be real.
Never pretend a model is a metric.
These are different things. The distinction must always be visible.

**Status bar enforcement:**

OBSERVED: LIVE ●    MODELED: STATIC ●    DATA TRUTH: VERIFIED

This line appears in the Engineer status bar at all times. It is the contract the workspace makes with the Inspector.

## NAVIGATION ARCHITECTURE

### Primary: Sidebar Hierarchy


0   System Topology        ← DEFAULT ENTRY
1   Project Inspection
2   Subsystem Inspection
3   Constraints & Tradeoffs


The Inspector descends. They do not browse.

Tabs are rejected because tabs imply flat siblings — all views equally accessible, equally weighted. The Engine Room is hierarchical. Level 0 is the only valid entry. Everything else is descended into by choice, not jumped to by convenience.

The sidebar communicates at all times:
- Where the Inspector is
- Where they came from
- How deep they can go

### Secondary: Breadcrumb Navigation

Rendered at the top of the main panel, always.


ENGINE ROOM  >  System Topology
ENGINE ROOM  >  CyberShield  >  Threat Engine
ENGINE ROOM  >  CyberShield  >  Threat Engine  >  Tradeoffs


Breadcrumbs make depth visible. The Inspector never loses their position.

### Navigation Rules

- Level 0 is accessible from any depth (clicking "System Topology" in sidebar resets to root)
- Level 1 requires selecting a project node at Level 0
- Level 2 requires selecting a subsystem node at Level 1
- Level 3 requires entering Level 2 first
- Simulations and Chaos Controls appear only at Level 1+
- No "Quick Inspect" shortcut. Descent is always earned.

### Tradeoffs View

MODELED surface. The highest privilege.


TRADEOFFS
Decisions and their costs

Why MongoDB?
  Reason      Flexible schema during rapid iteration
  Cost        Weaker relational guarantees
  Status      Accepted

  Reason      Instant persistence, zero infrastructure
  Cost        Not cross-device

## DESIGN CONSTRAINTS SPECIFIC TO ENGINEER MODE

**Relationship lines:** Line style differentiates type. Color does not. No rainbow relationships.

**Typography:** JetBrains Mono throughout. Same as design system.

**No red in UI.** Amber pulsing for critical states. Red only in log output [ERROR] entries.

**Node opacity:** Retired nodes render at 40% opacity, no fill. Visually subordinate but present.

**SIMULATION ACTIVE:** Rendered in amber (#C9924A) — borrowed from Recruiter accent. Only justified use of a foreign mode color. Signals: this is neither observed nor modeled. It is something you are doing deliberately.
